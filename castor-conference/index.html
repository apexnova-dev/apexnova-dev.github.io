Castor Conference App

A progressive web app for real conference operations: digital badges, staff scanning, geofenced self check-in, CEUs, certificates, and admin tooling — not a marketing microsite, but software meant for event day.

What it is

Castor is built for attendance workflows that have to work under pressure: sessions, rooms, registry exports, and attendees who may be offline or on mobile data. The stack is React, TypeScript, Vite, and Supabase — packaged as a PWA so staff and attendees can rely on it in the field.

This GitHub Pages page is the preproduction story for the project on apexnova-dev.github.io. The hosted app itself is deployed separately (for example on Vercel or another host) with your Supabase project and secrets — not from this static pitch.

Floor

Scanner flows, room QR, self check-in, and badges tuned for how conferences actually run.

Compliance

CEU tracking, certificates, evaluations, and exports aligned with registry-style reporting needs.

Control

Admin for sessions, registrations, announcements, vendors, and support paths when something breaks.

Where things stand

Active development continues in the repository: migrations, edge functions for room tokens, documentation for launch checklists, and hardening for production demos. Treat any public demo URL as staging unless you have explicitly promoted it for a live event.

Not the hosted app. This URL only describes Castor. To run or deploy the PWA, clone the repo, configure Supabase, and follow the project README and deployment docs.
