Void.md

Visual Kanban. Plaintext soul. No cloud. Markdown on disk is the database: the File System Access API reads and writes a granted folder, offline-first by design, with an optional GitHub Pages build for zero-install demos.

What it is

Void.md ships as a standalone web app (including a single void.html workflow): boards, filters, archives, rich notes (Tiptap) with Markdown fallback, and docs for AI-friendly column syntax. There is no hosted backend — storage is whatever Markdown and archives live in that workspace: Git-friendly, diffable, and suitable for air-gapped use.

This path (/void-md/) is a short summary on this hub. The canonical deploy from the Void.md repo lives at apexnova-dev.github.io/Void.md (see docs/github-pages.md there for branch build options).

Plaintext

kanban.md and archives — tasks stay in ordinary files: version, diff, and back up like any other repo content.

Browser-native

File System Access API for read/write to disk; optional telemetry; works when “no account” is a requirement.

Documented

Architecture, AI workflow, and column-ID rules so assistants and teams do not corrupt the board format.

Explore

The live Pages build is a zero-install demo; the repository documents local void.html + folder workflows and architecture. Product changes ship from Void.md on GitHub — not from this hub summary.
